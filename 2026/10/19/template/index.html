HTB - Paper Airplane (template only)

Created2026-10-19|Updated2026-10-19|HTBLinux
|Post Views:

Box: Paper Airplane (HTB, Medium, Linux)
Initial Access: SSRF in the PDF preview endpoint → AWS metadata → SSH key leak
Privilege Escalation: sudo on tcpdump → arbitrary file read → root

Enumeration

Nmap

Started with a standard service scan against the target.

Three services. SSH is likely only useful after we get credentials, so the focus is on 80 and 8080.

Web Recon

Port 80 hosts a marketing site for a fictional airline. Nothing interactive. Port 8080 is more interesting — Tomcat serving a “Document Preview” app that accepts a URL and returns a rendered PDF.

Directory brute-force on 8080 surfaced an admin panel that requires auth, but the preview endpoint itself is unauthenticated.

Foothold

Vulnerability Analysis

The /preview endpoint takes a JSON body:

The server fetches the URL server-side and returns a rendered PDF. This is a textbook Server-Side Request Forgery (SSRF) primitive: any URL we supply is fetched by the server, including internal addresses. If this box runs on AWS, the instance metadata service at 169.254.169.254 should be reachable.

Confirming SSRF

First, point the preview at our own listener to confirm the server makes an outbound request.

The listener logs a GET /test.pdf from 10.10.11.42. SSRF confirmed.

Hitting the Metadata Service

AWS IMDSv1 is reachable at 169.254.169.254 without a token.

Privilege Escalation

Enumeration

Standard Linux enumeration. The interesting hit is sudo -l.

tcpdump with sudo and NOPASSWD is a well-known privilege escalation primitive.

Exploit: tcpdump -z

tcpdump -z <file> runs <file> as root after each rotation. If we can trigger a rotation and control the command file, we get root code execution.

Root Flag

Lessons Learned

  • SSRF + cloud = metadata service. Any endpoint that fetches user-supplied URLs must block 169.254.169.254 (and the whole 169.254.0.0/16 link-local range).
  • Prefer IMDSv2. Enforcing IMDSv2 (session-token required) would have stopped the naive GET against the metadata endpoint.
  • Least-privilege IAM. The web role should not have had s3:GetObject on a backup bucket containing SSH keys.
  • sudo on network tools is dangerous. tcpdump, wireshark, nmap all have file-write primitives.
