OPSWAT CTF 2026 - Shortlink

Created2026-10-18|Updated2026-10-19|OPSWATCTF2026Web
|Post Views:

Challenge: Shortlink (Web)
Initial Access: Default credentials (admin:admin)
Privilege Escalation: Brute-forcing Flask secret key → Forging admin session cookie

Challenge Overview

We are presented with a simple web application that functions as a URL shortener. Upon visiting the main page, we are greeted with a login prompt.

Foothold

Default Credentials

Whenever I see a login page in a CTF, my first instinct is to try default credentials.

I tried admin:admin and successfully logged in. However, after logging in, I noticed that the application treated me as a standard user, and I did not have access to the administrative dashboard.

Analyzing the Cookie

Since the login was successful but privileges were restricted, the next step was to inspect how the application tracked my session. Looking at the browser’s developer tools, I found a session cookie named session.

Brute-Forcing the Secret Key

Flask session cookies are only secure if the SECRET_KEY is strong and unguessable. CTF challenges often use weak keys found in common wordlists.

Exploiting the Admin Panel

I replaced my current session cookie in the browser with the newly forged cookie and refreshed the page. The application immediately recognized me as an administrator.

Navigating to the admin panel, I found a list of pre-generated shortlinks. One link stood out: /go/DoGCqLU.

Looking at the target URL, it pointed to http://7f000001.08080808.rbndr.us:5001/flag. This is a classic DNS Rebinding payload designed to bypass SSRF protections:

  • 7f000001 is hex for 127.0.0.1 (localhost).
  • 08080808 is 8.8.8.8 (a public IP).
  • rbndr.us is a service that alternates between resolving to these two IPs.

When the shortlink was initially created (Time-of-Check), the server resolved the domain to the public IP 8.8.8.8 and allowed it. However, when I clicked the link to trigger the redirect (Time-of-Use), the server made a backend request to the URL. This time, rbndr.us resolved to 127.0.0.1, forcing the server to make an internal request to its own /flag endpoint on port 5001.

Clicking the shortlink successfully triggered the SSRF, and the server returned the flag.

Flag

Lessons Learned

  • Never use default credentials. admin:admin should never work in production.
  • Always use a strong SECRET_KEY. If a Flask secret key is weak or predictable, attackers can forge arbitrary session cookies and escalate privileges. Use a cryptographically secure random string (e.g., generated with secrets.token_hex(32)).
  • Session Security: Sensitive data like roles should ideally be verified server-side, or the application should use a more robust authentication mechanism (like JWTs or server-side session storage) rather than storing the user’s role in a client-side cookie.

Impact

This challenge demonstrates two critical vulnerabilities that, when chained, lead to full administrative compromise:

  1. Broken Authentication (Flask Session Forgery): By storing authorization roles in a client-side session cookie and protecting it with a weak cryptographic secret, the application allows attackers to forge their own admin tokens. In the real world, this leads to account takeover and unauthorized access to sensitive administrative functions.
  2. DNS Rebinding SSRF (TOCTOU): The shortlink feature attempts to prevent SSRF by requiring the target to resolve to a public IP. However, because DNS resolution is dynamic, an attacker can use a service like rbndr.us to pass the initial check (Time-of-Check) with a public IP, and then resolve to the internal loopback interface 127.0.0.1 (Time-of-Use).

Combined, these flaws allow an attacker to escalate to admin, pivot through the application’s backend, and access internal services that are otherwise blocked by the firewall.
